# 캡스톤 기획안 — 의류 이미지·치수 → 3D

> 범위 확정 기준: 대화에서 합의된 목표  
> **옷 이미지 + 치수 → (고객 수동 수정 없이) 로고·디테일이 보이는 3D**  
> 주력 품목: **반팔(티) + 바지**  
> 자켓은 확장/보류 (nearest 템플릿 한계)

---

## 1. 한 줄 목표

입력(정면 옷 사진 + cm 치수)을 넣으면, 서버가 자동으로  
**치수가 맞는 3D 의류(GLB/렌더)** 를 반환한다.  
로고·색·큰 프린트 등 **사진에 보이는 디테일**이 텍스처로 반영되어야 한다.

---

## 2. 하는 것 / 안 하는 것

### 한다
| 항목 | 내용 |
|------|------|
| 입력 | 옷 이미지(+권장 후면) + 품목별 치수 |
| 품목 | 반팔/티셔츠, 바지 |
| 자동화 | 업로드 → 분류/전처리 → 템플릿 매칭 → 치수 캘리브 → 텍스처 베이크 → 3D 출력 |
| 품질 | 치수 오차 목표 ~1–2cm, 로고·색이 GLB/렌더에서 식별 가능 |
| 사용자 | Blender 수동 편집 없음 |

### 하지 않는다 (이번 범위 밖)
| 항목 | 이유 |
|------|------|
| 자켓 Exact 메쉬 | 전용 템플릿 없음(nearest) — 데모 혼선만 큼 |
| 고객별 수동 모델링 | 서비스 성립 조건 위반 |
| 쇼핑몰 AR / 실측 피팅룸급 | 별도 제품 수준 |
| 뉴럴 Exact 기하 완전체 | 데이터·학습 의존 — **확장 모듈**로만 유지 |

---

## 3. 기술 아키텍처 (하이브리드)

```text
[입력] 이미지 + 치수
        │
        ▼
   Understand (분류, rembg)
        │
        ▼
   Template Match (tshirt / pants 전용 blend)
        │
        ▼
   Calibrate (Shape Key ↔ 재측정)     ← 치수 정확도
        │
        ▼
   Texture Bake (+ 선택 Silhouette)   ← 로고·색·디테일
        │
        ▼
   Export GLB / Render
        │
        ▼
   (선택) Neural P2 — 실패 시 템플릿 폴백
```

| 층 | 역할 | 이번 필수? |
|----|------|------------|
| P0 템플릿+캘리브 | 형태·치수 | **필수** |
| P1 텍스처(+실루엣) | 로고·색·윤곽 | **필수** |
| P2 뉴럴 | 일반화·세밀 기하 | 슬롯만 / soft 데모 |

핵심: **로고·디테일 = 텍스처 베이크가 본기능**.  
회색 OBJ만 보면 디테일이 안 보이므로 검증·발표 산출물은 **GLB/렌더** 기준.

---

## 4. 입력 스펙 (티 / 바지)

### 반팔·티
- 치수: `shoulder`, `chest`, `sleeve`, `length` (cm)
- 이미지: 정면 필수, 후면 권장 (로고·프린트가 선명)

### 바지
- 치수: `waist`, `hip`, `inseam`, `length` (cm)
- 이미지: 정면 필수, 측면/후면 권장

### 사진 가이드
- 배경 단순, 옷이 화면의 대부분
- 로고가 가려지지 않을 것
- 강한 주름·접힘 최소화

---

## 5. 성공 기준 (Acceptance)

1. **자동성**: API/앱 업로드만으로 결과 생성 (수동 메쉬 편집 0)
2. **치수**: 캘리브 후 주요 키 MAE 대략 ≤ 2cm (field soft는 문서화)
3. **디테일**: 입력 사진의 로고/큰 프린트/대표 색이 결과 GLB·렌더에서 육안 식별
4. **품목**: 티 입력 → 티 템플릿, 바지 입력 → 바지 템플릿 (자켓 nearest 혼동 없음)
5. **산출물**: 데모 영상/스크린샷 + accuracy 리포트 + 설계 문서

---

## 6. 단계 계획 (마일스톤)

캘린더 주 단위가 아니라 **완료 조건** 기준.

### Phase A — 범위 고정 & 실데이터
- 자켓 field_tape는 참고/보류, **티·바지**로 UI·벤치·발표 스토리 통일
- 실물 티 1 + 바지 1 (이미지+치수) field 케이스화
- 완료 조건: 케이스 JSON + fixture 이미지 커밋, 로컬 벤치 실행 가능

### Phase B — 텍스처를 본경로로
- field_pipeline / API 기본 옵션에 `bake_texture: true`
- rembg·UV 투영 품질 점검 (로고 위치·선명도)
- 완료 조건: 동일 입력으로 **로고가 보이는 GLB/렌더** 재현 가능

### Phase C — 치수·안정화
- 티/바지 calibration + field_pipeline 회귀
- 실패 시 폴백·에러 메시지 정리
- 완료 조건: release/soft 기준 문서화, 데모 시나리오 3회 연속 성공

### Phase D — 제품화 얇게
- 업로드 UI → 결과 뷰어(GLB)
- “이미지+치수 → 3D” 한 화면 데모
- 완료 조건: 비전공자도 따라 할 수 있는 데모 스크립트

### Phase E — 확장 (시간 남으면)
- 실루엣 보정 강화
- Neural stub → soft 데모 / 학습 데이터 수집 계획만
- 자켓 전용 메쉬는 **명시적 후속 과제**
